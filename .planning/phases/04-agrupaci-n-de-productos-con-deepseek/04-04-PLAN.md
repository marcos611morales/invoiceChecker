## Phase Goal

**As a** dueño, socio o contador del Coworking Café, **I want to** pedir a DeepSeek que agrupe como "mismo producto" los conceptos con descripciones distintas entre tiendas y que sugiera categorías, revisando cada sugerencia antes de aplicarla, **so that** nada cambia sin mi revisión y a DeepSeek solo llegan descripciones de conceptos y nombres de proveedor, por una ruta protegida.

<objective>
Run the one check that needs the user's key, right after the tracer and the server retry work end to end: JSON mode with thinking disabled, latency, empty or invalid answers and grouping quality on the golden set and on the real sample, then fix the batch limit and timeouts to the set the user chooses.

Purpose: RESEARCH marks JSON mode combined with disabled thinking (assumption A4), real latency (A3) and quality as unverifiable offline; finding a problem now costs one server module, finding it at the end of the phase would cost every later plan. The checkpoint is planner-emitted on purpose (orchestrator note 4) even though `workflow.human_verify_mode` is end-of-phase: it needs a secret only the user has and its result changes code in Task 3. «Sugerir categorías» (criterion 6) and cancel (criterion 7) do not exist yet; they are checked at the end of the phase in Plan 04-16.
Output: the golden fixture and evaluator, the opt-in live test, the user's measurements, and the chosen limits in the code.
</objective>
