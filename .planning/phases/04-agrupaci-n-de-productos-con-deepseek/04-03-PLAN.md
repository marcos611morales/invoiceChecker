## Phase Goal

**As a** dueño, socio o contador del Coworking Café, **I want to** pedir a DeepSeek que agrupe como "mismo producto" los conceptos con descripciones distintas entre tiendas y que sugiera categorías, revisando cada sugerencia antes de aplicarla, **so that** nada cambia sin mi revisión y a DeepSeek solo llegan descripciones de conceptos y nombres de proveedor, por una ruta protegida.

<objective>
Give accepted products a place to live: extend the persisted settings to version 3 (products and «No agrupar» marks, D-13) with a total migration from version 2, the integrity rules and limits, and the store, hook and backup controls carrying the six fields, so a Phase 3 user keeps every setting when this build opens.

Purpose: this is the real data layer of the accept slice (tracer pattern, step 2) and the one-way door of the phase; it ships alone so the type change and its migration are proven before Plan 04-05 writes the first product. D-09 and D-13 are user decisions rated one-way; they are cited, not re-gated (orchestrator note 3). The backup file keeps writing version 1 until Plan 04-10 adds file version 2. It runs in parallel with Plan 04-02 (no shared file).
Output: settings model, schema, migration and store at version 3, and the test helpers that write versions 2 and 3.
</objective>
