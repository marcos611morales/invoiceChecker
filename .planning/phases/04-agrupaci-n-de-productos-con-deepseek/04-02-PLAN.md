## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| route to api.deepseek.com | Untrusted statuses, headers and bodies come back; the key goes out |
| server logs | Vercel logs are readable by whoever administers the project |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-04-08 | Information disclosure | Key or upstream body echoed in a response, header or log | high | mitigate | taxonomy-only responses, one content-free console.info line, sentinel route tests over every upstream branch |
| T-04-09 | Information disclosure | Key or variable name inlined in the client bundle or prerendered HTML | high | mitigate | server-only modules, ESLint boundary, check-bundle-secrets with a DeepSeek sentinel over .next/static plus .html and .rsc |
| T-04-10 | Denial of service | Retry storms or a function killed by the platform before answering | medium | mitigate | at most 2 attempts, 170 s deadline, 20 s minimum budget, attempt timeout capped by the remaining time |
| T-04-11 | Elevation of privilege | Real DeepSeek calls from automated tests or smoke runs | medium | mitigate | smoke starts the server with an empty key; vitest stubs fetch; no test reads .env.local |
| T-04-12 | Information disclosure | Descriptions or supplier names in server logs | medium | mitigate | the log line carries counts and codes only; route test spies on console |
| T-04-SC | Tampering | npm installs | high | mitigate | nothing is installed (D-29) |
