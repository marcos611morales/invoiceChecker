| Destructive: button fill | `#E7000B`, white text | `#DC2626`, white text | Confirm buttons of destructive dialogs |

Contrast checks (WCAG AA: 4.5:1 text, 3:1 large text/UI):

| Pair | Light | Dark |
|------|-------|------|
| Foreground on background | 19.8:1 | 19.0:1 |
| Muted foreground on background | 7.8:1 | 7.8:1 |
| Muted foreground on secondary (the worst case) | 7.2:1 | 7.1:1 |
| Muted foreground on row hover / accordion hover | 7.2:1 (`secondary`) | 6.0:1 (hover `#262626`) |
| Text on accent button | 17.2:1 | 14.2:1 |
| Accent (focus ring, progress fill, drag-over border) on background | 17.9:1 | 15.7:1 |
| Destructive text on background | 4.8:1 | 6.9:1 |
| Destructive text on secondary | 4.4:1 (use only at 14px/600 or larger; see rule below) | 6.2:1 |
| White text on destructive button fill | 4.8:1 | 4.8:1 |

Rule for light destructive text on `secondary` (4.4:1, just under AA for small text): destructive text and icons must be placed on `background`, or be 20px+ / 28px numerals (large text, 3:1 required) when on `secondary`. The "Rechazados" summary card value is Display size (28px), so it passes; its sub-label stays in muted foreground, not destructive. Rejected-file row reasons are in foreground color, only the icon is destructive.

Accent reserved for (and nothing else):

1. Primary buttons: "Entrar", "Seleccionar archivos", "Agregar facturas".
2. Dropzone drag-over state: border turns solid accent; window-wide drop overlay border.
3. Progress bar fill.
4. The active sort icon (ArrowUp/ArrowDown) in the table header.
5. The 2px keyboard focus ring (`ring` token set to accent, 2px offset) on all focusable elements.

Destructive reserved for:

1. The confirm buttons in the "Cerrar sesión" and "Quitar todas" dialogs.
2. The "Contraseña incorrecta" / login error message text.
3. The numeric value and the row icon of the "Rechazados" group.

Everything else (warnings such as "Receptor distinto", duplicates, ignored files) uses neutral foreground/muted text plus an icon and a text label. No third semantic color is introduced in this phase; color is never the only carrier of meaning (every status also has text).

### Theme implementation [user-confirmed]

Behavior:

- Two states only, Claro and Oscuro, switched by one toggle button (no 3-option menu, no "Sistema" entry). Until the user clicks it, the theme is the OS preference and updates live if the OS preference changes (`matchMedia("(prefers-color-scheme: dark)")` change listener). On the first click the toggle flips to the opposite of the currently displayed theme and stores that choice; the listener then stops affecting the theme. There is no way back to "follow the OS" other than clearing site data (accepted consequence of the two-state design).
- Persistence: `localStorage` key `invoicechecker:theme`, value `"light"` or `"dark"`. Every `localStorage` read and write is wrapped in `try/catch`; if storage is unavailable, blocked or holds an invalid value, fall back to the OS preference and keep working (the choice just does not persist). It is a UI preference, not invoice data, so it is not cleared on logout, on "Quitar todas" or on reload.
- No dependency is added for this (CLAUDE.md lists none): a small hand-written hook reads the `dark` class on `<html>` (for example through `useSyncExternalStore` with a `MutationObserver`) and exposes the active theme to the toggle and to the Toaster.

Implementation in the code:

- `globals.css`: light tokens on `:root`; dark tokens in a `.dark { ... }` block; `@custom-variant dark (&:where(.dark, .dark *));`. This replaces the shadcn-generated `@custom-variant dark (&:is(.dark *))` line; the executor edits it after `shadcn init`. Add `color-scheme: light` on `:root` and `color-scheme: dark` on `.dark` so native scrollbars, the file picker and form controls match.
- Pre-hydration script: a tiny inline `<script>` as the first child of `<head>` in the root layout. It reads `invoicechecker:theme` (inside `try/catch`), falls back to `matchMedia("(prefers-color-scheme: dark)").matches`, and adds the `dark` class to `document.documentElement` before first paint, so there is no flash of the wrong theme.
- `<html lang="es-MX" suppressHydrationWarning>`: required because the script changes the `class` attribute before React hydrates.
- Components use semantic tokens (`bg-background`, `bg-secondary`, `text-muted-foreground`, `border-border`, ...) and never literal hex or `bg-white` / `text-black`, so both themes work without per-component `dark:` classes. The window drop overlay uses the `background` token at 90% opacity.
- Sonner: `<Toaster theme={activeTheme} />` where `activeTheme` is `"light"` or `"dark"` from the hook above (not `"system"`), so toasts follow the toggle as well as the OS.
- The toggle button must not cause a hydration mismatch: render both icons and show one with CSS (`dark:hidden` on Moon, `hidden dark:block` on Sun) instead of choosing the icon in JavaScript; the accessible name and tooltip text are set after mount from the hook, and before mount the `aria-label` is the neutral "Cambiar tema".

Verification checks (for the verifier):

- Login, empty dropzone, loaded report, table and both dialogs rendered in dark; focus ring and drag-over border visible on `#0A0A0A`.
- First load with the OS in dark and storage cleared: page paints dark immediately, no flash of light.
- Click the toggle, reload: the chosen theme is kept even when it differs from the OS. Block `localStorage`: the app still loads and follows the OS.

## Layout & Interaction Contract

### Routes and shell

- `/login`: full-height page on the `secondary` surface, one Card (384px) centered both axes, no top bar, no logo [D-04]. The theme toggle is positioned fixed at the top-right of the viewport (16px from the top and right edges), outside the card, so the card keeps exactly the D-04 content. [user-confirmed] Content: app name (Heading), subtitle (Body, muted), Field "Contraseña" with InputGroup (password input + trailing icon button Eye/EyeOff), error message area, full-width primary Button "Entrar".
- `/` (everything else redirects to login through the proxy): top bar + `main` (max-w 1152px, horizontal padding 24px, top padding 32px, bottom 64px, sections separated by 32px).
- Top bar [D-06]: sticky, 56px, `secondary` surface, 1px bottom border. Left: app name. Center: an empty `flex-1` slot reserved for the future IVA selector and export button (render nothing now, keep the slot so later phases do not reflow the bar). Right cluster, in this order with 8px gaps: "Agregar facturas" (primary, Upload icon; rendered only when invoices are loaded [D-10]), the theme toggle, "Cerrar sesión" (ghost, LogOut icon). The center slot stays reserved for the IVA selector and export; the toggle lives in the right cluster so it does not take that space.
- Theme toggle [user-confirmed]: ghost icon-only button, 36x36px (44x44px under 640px), `Moon` icon in light theme (action: go dark) and `Sun` icon in dark theme (action: go light), 20px, decorative (`aria-hidden`), accessible name and Tooltip from the Copywriting Contract. Same component, placement and behavior on every screen where it appears (`/login` and the app shell). Always enabled, including while a batch is processing. Keyboard: Tab-focusable, Enter/Space activates, 2px accent focus ring. Switching has no animation beyond the 150 ms color transition (removed with `prefers-reduced-motion`).

### Login behavior

- Password field autofocused, `autocomplete="current-password"`, Enter submits. Toggle button is `type="button"`, keeps focus on itself, flips `aria-label` and `aria-pressed`.
- On submit: button disabled with Spinner and "Entrando…" during the request and the ~1 s delay [D-03]; the form cannot be double-submitted.
- On failure: error text (destructive, with CircleAlert icon) below the field, `role="alert"`, field gets `aria-invalid="true"` and `aria-describedby`; the field is re-focused and its content selected. The error clears when the user types.
- On success: navigate to `?next=` if it is an internal path (starts with `/`, not `//`), else `/` [D-05].
- Session lasts 30 days [D-01]; no "recordarme" checkbox.

### Empty screen (no invoices) [D-09, D-24, D-25]

- One large Card, dashed 1px border (`#E5E5E5`), min height 256px, padding 48px 24px, content centered: CloudUpload icon (40px, muted), Display heading, Body text, the two buttons side by side (stack vertically under 640px), then below the buttons the Label-size privacy line with a ShieldCheck icon and, under it, the reload note (muted).
- The whole window is a drop target. Dragging files over it switches the card to the drag-over state (solid accent border, `secondary` fill, drag-over text).
- Buttons: "Seleccionar archivos" opens a multi-file picker; "Seleccionar carpeta" opens the directory picker. Neither restricts by extension (no `accept=".xml"`), otherwise PDFs and ZIPs could not be reported as ignored.

### Loaded screen [D-10]

- The dropzone card is removed. The top bar shows "Agregar facturas". Dropping files anywhere on the window shows a fixed full-viewport overlay (`background` token at 90% opacity, 2px dashed accent inset border 16px from the edges, centered "Suelta para agregar facturas" in Display size) with `pointer-events` only for the drop; it disappears on drag leave/drop.
- Vertical order: (1) processing indicator when active, (2) report header row: heading "Reporte de importación" left, "Quitar todas" (outline) right, (3) summary cards grid, (4) accordions, (5) "Facturas cargadas" section, (6) footer caption with ShieldCheck + the privacy line (so the privacy statement stays visible after the dropzone is gone). [user-confirmed]
- Report accumulates all batches of the session [D-20, D-08]. A new drop never replaces earlier data; only "Quitar todas" or logout clears it.

### Processing [D-11]

- While the files are being listed (folder traversal), show Spinner + "Leyendo archivos…". Once the count is known, show Progress (accent fill, 8px tall, full width inside a Card) with "Procesando {N} de {M}" above it. Update at most every 100 ms; the text container has `aria-live="polite"` and `aria-atomic="true"`, and the Progress has `aria-valuenow/min/max` and `aria-label="Progreso de importación"`.
- While a batch is processing, "Agregar facturas", "Seleccionar archivos/carpeta" and "Quitar todas" are disabled and window drops are ignored (the overlay is not shown). [user-confirmed]
- When the batch ends: the indicator unmounts, the toast fires, the report and table update, and the heading of the report section receives no focus change (do not steal focus).

### Summary cards [D-19]

- Grid: 2 columns under 640px, 3 columns 640–1023px, 4 columns from 1024px; 16px gap. Card: `secondary` surface, 1px border, padding 16px. Content: label (Body, 600), value (Display, `tabular-nums`), optional sub-label (Label, muted).
- "Traslado y nómina" is not rendered at all when both are 0. Other cards always render, with value 0 when empty (value in muted color).
- "Rechazados" value and CircleAlert icon use the destructive color when greater than 0.
- Cards are informational, not interactive.

### Accordions [D-19]

- Sections, in order: Rechazados, Receptor distinto, Duplicados, Ignorados, Ingreso, Egreso, Pago, Traslado y nómina. A section renders only if its count is greater than 0. `type="multiple"`.
- "Rechazados" is open by default when it has files; all others closed [D-19]. "Rechazados" re-opens automatically when a later batch adds rejections.
- Trigger: Body 600 text "{Group} ({count})", chevron on the right, full-width, 40px tall, hover `secondary`, keyboard operable (Enter/Space), `aria-expanded` provided by the component.
- Panel: file list inside ScrollArea (max-height 320px). Each row: file name in Geist Mono 12px truncated with an ellipsis and Tooltip with the full name, then the reason/detail in Body below it (wraps, never truncated). Row padding 8px 16px, 1px separators. Rejected rows prefix a CircleAlert icon (destructive); others have no icon.
- Files listed per group are those of the whole session. Order within a group: order of arrival.

### "Facturas cargadas" table [D-21..D-23]

- Built with TanStack Table (v9 API) over the session store; display only, no totals row and no sums of any kind [D-22].
- Columns, in order, with alignment: Fecha (left, `dd/mm/yyyy` produced by slicing the literal ISO string `YYYY-MM-DD` of the CFDI `Fecha`; never through `new Date`), Proveedor (left, issuer name, truncated at 280px with Tooltip), Tipo (left, outline Badge), Folio (left, Geist Mono, "—" if absent), Total (right, `Intl.NumberFormat("es-MX", { style: "currency", currency: <XML Moneda> })`; "—" when currency is `XXX`), Conceptos (right, integer).
- Sorting [D-23]: every header is a button that cycles ascending, descending, unsorted; shows ArrowUpDown (muted) when unsorted and ArrowUp/ArrowDown (accent) when sorted; the `th` carries `aria-sort`. Fecha sorts by the literal ISO string; Total sorts numerically on the XML value; Tipo and Proveedor sort alphabetically with `es` collation. Default sort: Fecha descending. [user-confirmed]
- Pagination [D-23]: 50 rows per page, shown only when there is more than one page. Footer: left "Mostrando {a}–{b} de {n}", right "Página {p} de {P}" and the buttons "Anterior" / "Siguiente" (outline, disabled at the ends). Changing sort or adding a batch keeps the current page if it still exists, otherwise goes to page 1.
- Rows: 40px, hover `secondary`, header `secondary` with 600 weight. Under 768px the table scrolls horizontally inside its container (the page itself never scrolls horizontally); the Fecha column stays visible first.
- Table is wrapped in a labelled region (`aria-labelledby` the section heading). Caption/heading text is the one defined in the copy contract.

### Dialogs

- AlertDialog from shadcn. Focus lands on "Cancelar"; Esc and click on the overlay cancel; the destructive button is last. Confirming "Cerrar sesión" clears the in-memory store, calls the logout endpoint, then navigates to `/login`. Confirming "Quitar todas" clears the store and returns to the empty screen without navigation.

### Accessibility floor

- All controls reachable and operable by keyboard; visible 2px accent focus ring.
- The theme toggle's accessible name always names the action it performs, not the current state.
- Contrast: AA in both themes per the Color contrast tables (muted text verified on the dark `secondary` surface at 7.1:1).
- Drag-and-drop is never the only path: the buttons always work.
- Results announced: toast (Sonner is `aria-live`), progress text (`aria-live`), login error (`role="alert"`).
- Transitions (accordion, overlay fade) are 150 ms and removed when `prefers-reduced-motion: reduce`.
- Icon-only buttons have an `aria-label`; decorative icons have `aria-hidden="true"`.
