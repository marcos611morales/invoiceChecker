# Phase 5 — UI Design Contract

> Visual and interaction contract for frontend phases. Generated by gsd-ui-researcher, verified by gsd-ui-checker.
> All user-facing copy is Spanish (es-MX). The app is single-locale; no i18n framework. Static strings go in `src/lib/copy/es.ts`, interpolated sentences in `src/lib/copy/messages.ts`, money and dates in `src/lib/format.ts`.
>
> This phase **extends** `01-UI-SPEC.md` to `04-UI-SPEC.md` (all approved). Tokens, the 4 type sizes, the 2 weights, the spacing scale, theme behavior, top bar, the 44px touch-target rule, the Tooltip / tap-Popover rule for truncated text (`TruncatedText`), the "Deshacer" toast rule (6 s, bottom-right, closable), the inline-edit pattern, the expandable-row table pattern, the "bordered `background` block with 24px padding" section look, the `secondary` KPI-card look and the accessibility floor stay in force and are **not repeated** unless this phase adds to them. "As Phase N" means follow that phase's contract exactly. The new tab must look like the same app: same 20/600 headings with a 12px muted intro, same row captions, same table chrome as `InvoiceTable` / `ProductList`.
>
> Source key: **[D-nn]** = locked decision in 05-CONTEXT.md (decisions of earlier phases are cited as **[P1 D-nn]** … **[P4 D-nn]**). **[P1]** … **[P4]** = rule inherited from that phase's UI-SPEC. **[CLAUDE.md]** = stack decision locked by the user. **[default]** = low-risk value chosen by the researcher because no upstream artifact answers it (all listed under "Defaults taken"). **[OQn]** = open question for the user, with a recommended answer already applied in this draft (listed under "Open questions"). Per the project rule "ask, never infer", every OQ must be confirmed or changed by the user before the planner treats the row as locked.

## Spacing Scale

Same scale as Phases 1 to 4 (multiples of 4; Tailwind 1 unit = 4px): xs 4 · sm 8 · md 16 · lg 24 · xl 32 · 2xl 48 · 3xl 64. Usage in this phase:

| Token | Value | Usage in this phase |
|-------|-------|---------------------|
| xs | 4px | Icon-to-text gap, gap between a value and its caption, gap between a store name and its badge |
| sm | 8px | Gap between tools-row items, between buttons in the editor, between legend glyph and label |
| md | 16px | Savings-card padding, gap between the savings card and the tools row, expanded-panel padding under 640px, chart legend row gap |
| lg | 24px | Padding of the bordered products block, expanded-panel padding from 640px, gap between the sections of the expanded panel, legend horizontal gap (24px, as the trend legend) |
| xl | 32px | Gap between the sections of the Precios tab, between tab list and panel |
| 2xl | 48px | Empty-state vertical padding |
| 3xl | 64px | Page bottom padding |

Exceptions (all multiples of 4, outside the 7-step scale on purpose):

- Everything listed as an exception in Phases 1 to 4 stays (top bar 56px, `max-w-6xl` 1152px, 44px touch targets under 640px, table row 40-56px, 288px list max height, tab list 44px under 640px).
- Products table: row min height 56px; table min width 880px inside `overflow-x-auto` (the page never scrolls horizontally); expand column 48px; actions column 48px.
- Search field: 36px tall (44px under 640px), 320px wide (full width under 640px). The checkbox row is 44px tall under 640px.
- Per-store table: min width 640px inside `overflow-x-auto`; row min height 48px.
- Purchases list: min width 880px inside `overflow-x-auto`; row min height 48px.
- Content table: min width 760px inside `overflow-x-auto`; row min height 56px; inline editor fields: quantity `Input` 120px, unit `Select` trigger 120px, pieces-per-pack `Input` 96px, all 36px tall (44px under 640px, full width each, stacked).
- History chart: height 288px (`h-72`, same as the trend chart); Y axis width 64px (unit prices carry cents); data markers 10px with a 2px `background` ring; lines 2px.
- **Tab list: the horizontal scroll that Phase 3 applied under 640px now applies under 768px** (six triggers do not fit between 640 and 767px; STATE.md already records a 17px overflow at 640px with five). Mechanically: the `max-sm:` modifiers on `TabsList` (`max-sm:justify-start max-sm:overflow-x-auto` and the hidden scrollbar) become `max-md:`; the 44px height stays `max-sm:` (touch targets), and the active trigger is still scrolled into view on change. No label is shortened.

## Typography

Exactly the Phase 1 set: **4 sizes and 2 weights**. Nothing new.

| Role | Size | Weight | Line Height | Used in this phase for |
|------|------|--------|-------------|------------------------|
| Body | 14px | 400; 600 for buttons, labels, tab triggers, product names, the cheapest store's price, table headers, savings amounts in the products table | 1.5 | Table cells, Select values, inputs, toasts, alert text, checkbox label |
| Label / caption | 12px | 400 (600 for table column headers) | 1.5 | Section intros, captions under a value ("estimado", "n compras", dates under "Último"), badges, legend, chart axis ticks and tooltips, helper and error text, the savings-card note |
| Heading | 20px | 600 | 1.2 | "Precios", the sub-section headings of the expanded panel are **14/600 Body**, not Heading |
| Display | 28px | 600 | 1.2 | The single total in the "Ahorro estimado" card (same look as a KPI value) |

Rules (additions):

- All prices, contents, counts and dates use `tabular-nums`. Prices and savings are never truncated or abbreviated (chart axis ticks may use compact notation, as Phase 2).
- Descriptions, product names and store names are vendor/user data: render only as React text (never HTML), keep original case, wrap in the expanded panel and truncate (`TruncatedText`) only inside a products-table cell.
- Units always follow the number with a normal space: "35.20 $/kg" is **not** used; the form is «{precio} / kg» (e.g. «$35.20 / kg»), «{precio} / L», «{precio} / pieza». Contents: «2 kg», «0.375 kg», «12 L», «12 × 355 mL», «6 piezas», «1 pieza».
- No other sizes or weights anywhere in the phase.

Implementation: add the six custom properties to `:root` and `.dark` in `globals.css` and map them in `@theme inline` as `--color-series-1` … `--color-series-6` (same pattern as `--color-chart-1`). The chart config is static: keys `tienda1` … `tienda6` and `otras` map to `var(--series-n)` / `var(--chart-1)`; store names are never keys.

**Palette validation (run 2026-10-25, `validate_palette.js`, 6 slots, in this fixed order, against the app surfaces `#FFFFFF` and `#0A0A0A`).** Light: lightness band PASS, chroma PASS, adjacent CVD separation PASS (worst ΔE 9.1, `#EDA100`↔`#1BAF7A`), normal-vision floor PASS (worst 19.6), contrast vs surface **WARN** (slots 3, 4 and 5 are 2.82, 2.17 and 2.69 against `#FFFFFF`). Dark: all five checks PASS (worst adjacent CVD ΔE 8.4, normal-vision 19.3, all slots at least 3:1). **Relief for the light-mode WARN (mandatory, not optional):** (1) every series also has its own marker shape, so identity is never color alone; (2) the legend is always present with glyph + store name; (3) the purchases list under the chart is the table view of the same data; (4) the tooltip names the store in text. The order is the validated adjacent order and is **never cycled or reordered**.

**Series assignment rule [default, OQ1]:** the slot of a store is its position in the alphabetical list (`es`) of the stores that sold *that product* in the **unfiltered** comparable purchases, so changing a date or supplier filter never repaints the surviving stores. Stores beyond the sixth are folded into one neutral series «Otras tiendas ({n})» drawn with markers only (no connecting line, since it mixes stores); their tooltip still names the store. Text never wears a series color: store names, values and legend labels stay in `foreground` / `muted-foreground`.

Rules:

- 60/30/10: the Precios tab sits on `background`; the savings card, table headers, hover and the expanded panel on `secondary`; accent stays small. The cheapest store row is `background` inside the `secondary` expanded panel (a lifted row), plus the badge and the 600 weight: the highlight is never color alone.
- Non-comparable rows (shown with «Mostrar los no comparables») and non-normalized purchases are de-emphasised with `text-muted-foreground` text (not with opacity), so contrast stays at the approved muted-on-background 7.8:1 / 7.2:1 on `secondary`.
- Contrast: only pairs already approved in Phases 1 to 4 are used for text. `--positive` on `background` and on `secondary` is 6.5:1 light / 10.3:1 dark (Phase 2 table).
- A saving is a good outcome but **not** painted with `--positive`: the savings amounts are `foreground`. (Phase 2 reserved `--positive` for the "decreased" delta; this phase adds only the cheapest-store check.)

Accent reserved for (Phase 4 list; **this phase adds nothing and removes nothing**):

1. Primary buttons: "Entrar", "Seleccionar archivos", "Agregar facturas" (still the only accent-filled button on any non-modal screen; every button in Precios is `outline` or `ghost`).
2. Dropzone drag-over state and the window drop overlay border.
3. Progress bar fill (not used in this phase).
4. The active sort icon in any table header (including the products table of Precios).
5. The 2px keyboard focus ring on all focusable elements.
6. The 2px underline of the active tab (now six tabs).
7. The confirm button of the two modal dialogs of Phase 4 (this phase has **no modal dialog**).

Destructive reserved for: unchanged from Phase 4. **Nothing in this phase uses destructive.** «Marcar como no comparable», «Volver a lo detectado» and «Quitar corrección» are reversible with «Deshacer» and use neutral buttons.

## Layout & Interaction Contract

### Primary focal point per screen

| Screen | Primary focal point | How it is established |
|--------|---------------------|-----------------------|
| Precios, with data | The «Ahorro estimado» card, then the products table | Only block with a 28/600 numeral on `secondary`; the table below is on `background` at 14px. No accent-filled button. |
| Precios, no products | The `Empty` state with «Ir a Productos» | Nothing else renders. |
| Expanded product | The summary line «Más barata: …» | First text in the panel, 14px with the `Check` badge on the lifted store row just below it. |

### Shell and tabs [D-01]

- Six tabs. `AppTab` gains `"precios"`; `isAppTab`, `TABS`, the trigger map and the `TabsContent` list in `AppShell.tsx`, and `es.tabs.prices` are extended. Same trigger styling (14/600, 40px list, accent 2px underline). Position after «Productos».
- The list scrolls horizontally under **768px** (see Spacing exceptions). **The verification run must check 360, 640, 767, 768 and 1024px** and confirm that no page-level horizontal scroll appears.
- The tab content is computed from the **filtered** ledger of the session (`useDashboardView`-style selectors) and the settings store; nothing is stored by this tab except the two settings listed under Persistence.

### Precios tab composition

Vertical order, 32px gaps: (1) title row (Heading + intro), (2) filter bar + mode captions, (3) settings write-failure Alert when present, (4) «Ahorro estimado» card, (5) tools row, (6) products block. The empty states replace (2) to (6) as described in the copy table (empty state 1 replaces everything but the heading; states 2 and 3 keep the filter bar and, for state 3, the tools row).

- **Filters (2) [D-03, FILT-05, OQ2]:** the existing `FilterBar` (dates, proveedor, forma de pago, categoría, chips, mobile fold) is rendered in this tab exactly as in the Dashboard, bound to the same session-store filters, so changing a filter here changes it everywhere. The IVA toggle in the top bar keeps working [D-04]. No new filter exists.
- **Savings card (4):** the KPI-card markup of `KpiRow` (`secondary`, 1px border, 16px padding, 4px between rows), full width up to `max-w-[480px]` on desktop, full width under 640px. Rows: label + «estimado» badge, value, sub-label, note. Informational, not interactive.
- **Tools row (5):** left, the search field; right (wraps below under 640px), the «Mostrar los no comparables ({n})» checkbox and the count line. Search matches the product name, case- and accent-insensitive (same comparable-name normalization as the product names), and narrows the table; it does not change the savings card (the card follows the filters, not the search) **[default]**.
- **Products block (6):** bordered `background` surface with 24px padding, the TanStack table, pagination above 50 rows. Row min height 56px; the product name is 14/600, wraps up to 2 lines and then truncates with `TruncatedText`; the badges sit under the name on their own line; Precio, Tiendas and Ahorro are right-aligned.

### Products table behavior [D-02, D-06, D-07, D-20]

- Rows: every accepted product with at least one qualifying purchase in the filtered set, comparable by default or by the user's choice. Stores are suppliers by RFC, shown by supplier name [D-05]. Only lines of invoices that count [D-06] feed prices; credit notes never change a price.
- Expanding a row (button in the first column, `aria-expanded`) opens a `secondary` panel spanning the table width; several rows can be open at once. Expanded state is not persisted.
- Sorting: one-click `SortHeaderButton` on the four sortable columns; the active sort icon is the accent (Phase 3 list). "Rows with no saving last" holds for the Ahorro descending default; for other sorts, rows with no value sort last in both directions.
- The "⋯" menu has the one item of the current state. Choosing «Marcar como no comparable» removes the row from the visible list (unless the checkbox is on, where it stays, de-emphasised), shows the toast, and **moves focus to the section heading «Precios»** (the row is gone). With the checkbox on, focus stays on that row's "⋯" button. «Deshacer» restores the previous effective state exactly.
- Non-comparable rows (checkbox on) are de-emphasised as described in Color, have no expander, and their "⋯" menu offers «Volver a comparar».

### Expanded panel [D-07, D-08, D-12, D-13, D-20, D-24]

A `secondary` panel, padding 16px under 640px and 24px from 640px, sections separated by 24px, in this order (sections with nothing to show are not rendered):

1. **Alerts:** the mixed-families note and/or the missing-content notice, when they apply.
2. **Summary:** the summary line and its 12px continuation; the family line.
3. **Precios por tienda:** plain `Table`, one row per compared store, sorted by Mediana ascending (so the cheapest store is first); the cheapest row is lifted and badged. Stores whose purchases are all non-normalized are not listed here (they appear in the content and purchases sections).
4. **Historial de precios:** the chart card (see below).
5. **Contenido de cada descripción:** the editable member table [D-13]; shown only for products that have at least one member with purchases. Members are ordered: «No normalizado» first, then corrected, then detected; ties by description (`es`).
6. **Compras:** the purchases list [D-08].

**History chart [D-24]:** a `LineChart` inside `ChartContainer` (static config, `aspect-auto h-72 w-full`, `accessibilityLayer`). X axis: a numeric time axis of the purchase dates (literal CFDI date, no time-zone conversion, as P2 REGLA-05), ticks formatted «may 2025» (es-MX, short) and thinned with `preserveStartEnd` above 12 ticks. Y axis: normalized price, ticks via `Intl.NumberFormat("es-MX", { notation: "compact" })`, 64px wide, domain padded 10% and never forced to start at zero (a price line, not a magnitude bar). Hairline gridlines horizontal only (`var(--border)` at 50%), as `TrendChart`. One `Line` per store in date order: 2px, `type="linear"`, `connectNulls` off, `isAnimationActive={false}`, color `var(--color-tiendaN)`; each purchase is a 10px marker of that store's shape with a 2px `background` ring; the folded series draws markers only. `ChartTooltip` is per mark (`shared={false}`), custom content as in the copy table; markers have a hit area of at least 24px. The legend is an HTML row under the chart (`flex flex-wrap gap-x-6 gap-y-2`, 12px muted text, glyph in the series color/shape and the store name in muted text), always present. The chart is wrapped in `role="img"` with the `aria-label` of the copy table; the purchases list under it is the accessible table view, so no second `sr-only` table is added. Under 640px the same chart is used at the same height (the plot is not scrollable; ticks thin out).

**Content editor [D-13, D-14, D-15]:** the pencil (or «Capturar contenido») turns the content cell of that row into an inline editor in a row spanning the table (fields in one row from 640px, stacked and full width under it): «Piezas por paquete» (integer, default 1), «Contenido de cada pieza» (decimal) and «Unidad» (Select: g, kg, mL, L, piezas), the helper line, the live preview line and the three buttons. Focus goes to the first field on open; Enter saves when valid; Esc discards; after Save or Discard, **focus returns to that row's pencil**. Saving recomputes prices, the cheapest store, the savings, the chart and the card immediately, and persists. The editor exists only for members whose SAT unit is a piece unit [D-14]; members whose unit is weight or volume show the «Usa la cantidad del XML» text and no edit button. «Volver a lo detectado» removes the correction (with the toast and «Deshacer»). The correction follows the member (RFC + normalized description, P4 D-09), as 05-CONTEXT proposes.

**Purchases list [D-08]:** plain `Table` in `overflow-x-auto`; non-normalized rows keep their place in date order with muted text and the reason caption in the Contenido cell; they have no price and no marker in the chart. The list is the only place where every purchase of the product (normalized or not) is visible.

### Persistence contract (UI-visible parts) [D-15, D-19]

- Content corrections and «no comparable» overrides live in `invoicechecker:settings` (version 4) and in the backup file; backups of earlier versions keep loading with empty lists. Only what the user changed from the default is stored [D-19].
- Both are written on every change; every storage call stays in `try/catch`; failures use the storage notice above. The Precios tab adds no new notice for the backup file (the existing replace-settings dialog summary is extended by the planner to count corrections and overrides; copy: «{n} correcciones de contenido, {m} marcas de no comparable», zero parts shown as «0 …» like the Phase 4 summary).
- The search text, the checkbox «Mostrar los no comparables», the expanded rows and the sort are session-only state and are not persisted.

### Accessibility floor (additions)

- Tabs: six triggers with roving arrow keys, `aria-selected`.
- The products table has `aria-sort` on the sorted header (`ariaSort`), real `<table>` semantics, `scope` on headers; the expander and the "⋯" button carry the product name in their `aria-label`; the Tooltip repeats it for icon-only buttons.
- The «Más barata» highlight is text + icon + weight, not color. The series are told apart by marker shape and legend, not hue alone.
- The checkbox has a visible label; the search `Label` is `sr-only`.
- Editor: labels on every field, `aria-invalid` + `aria-describedby`, the preview is a polite live region.
- Live regions (polite): the product count after search/marking, the "marcado como no comparable" announcement, "Contenido guardado".
- Toasts with actions stay 6 s and are keyboard reachable [P2]. Transitions 150 ms removed under `prefers-reduced-motion`; the chart is not animated. No new animation is introduced.
- Contrast: AA in both themes; the only sub-3:1 graphic colors are the light-mode series slots 3 to 5, with the relief listed under Color.
- Vendor descriptions and supplier names are untrusted: React text only, no `dangerouslySetInnerHTML`, no markdown, and never used as chart-config keys.
