# Phase 3 — UI Design Contract

> Visual and interaction contract for frontend phases. Generated by gsd-ui-researcher, verified by gsd-ui-checker.
> All user-facing copy is Spanish (es-MX). The app is single-locale; no i18n framework. Static strings go in `src/lib/copy/es.ts`, interpolated sentences in `src/lib/copy/messages.ts`, money and dates in `src/lib/format.ts`.
>
> This phase **extends** `01-UI-SPEC.md` and `02-UI-SPEC.md` (both approved). Tokens, the 4 type sizes, the 2 weights, the spacing scale, theme behavior, top bar, touch-target rule, Tooltip/tap-Popover rule for truncated text and the accessibility floor stay in force and are **not repeated** unless this phase adds to them. "As Phase 2" means follow the Phase 2 contract exactly.
>
> Source key: **[D-nn]** = locked decision in 03-CONTEXT.md (decisions of Phase 2 are cited as **[P2 D-nn]**). **[P1]** / **[P2]** = rule inherited from the Phase 1 / Phase 2 UI-SPEC. **[CLAUDE.md]** = stack decision locked by the user. **[default]** = low-risk value chosen by the researcher because no upstream artifact answers it (listed under "Defaults taken"). **[OPEN Qn]** = value that is provisional until the user answers question n in "Open questions" (project rule: ask before inferring). Nothing marked **[OPEN]** may be treated as final by the planner.

- Supplier table (section 2): row min height 56px; table min width 900px inside a horizontally scrollable container (the page never scrolls horizontally); Select trigger width 296px (full width of its cell under 640px); actions column 160px.

- Top bar: "Exportar a Excel" is 36px tall; icon-only below 1024px it is 36x36px (44x44px under 640px), like the other top-bar icon buttons.
- Tab list under 640px: height 44px and horizontal scroll (see Layout).

## Color

**No token is added or changed.** The Phase 2 tokens (`background`, `secondary`, `border`, `muted-foreground`, `primary`, `destructive`, `destructive-fill`, `--chart-1`, `--positive`) cover everything. Categories do **not** get individual hues: one neutral bar color keeps the 60/30/10 split and avoids a palette that would not survive both themes.

| Role | Light | Dark | Usage in this phase |
|------|-------|------|---------------------|
| Dominant (60%) `background` | `#FFFFFF` | `#0A0A0A` | Page, category block card, categories list card, dialogs, popovers |
| Secondary (30%) `secondary` | `#F5F5F5` | `#171717` | Top bar, table header rows, row hover, expanded concept panel, filter chips, the locked "Sin categoría" row |
| Accent (10%) `primary` | `#171717` | `#E5E5E5` | See reserved list |
| Destructive | `#E7000B` / fill `#E7000B` | `#FF6467` / fill `#DC2626` | See reserved list |
| `--chart-1` | `#737373` | `#A3A3A3` | Fill of the category bars (same as supplier bars) |
| `--positive` | `#166534` | `#4ADE80` | Category variation that **decreased** [D-17, P2 D-20] |
| Muted foreground | `#525252` | `#A3A3A3` | Captions, "del proveedor" suffix, "Sin categoría" implicit value, dimmed concept rows, "Sin dato del mes anterior" |

Contrast: the pairs used here already exist in the Phase 1/2 tables (muted on background 7.8:1 / 7.8:1, muted on secondary 7.2:1 / 7.1:1, `--chart-1` on background 4.7:1 / 7.9:1, `--positive` on background 7.1:1 / 11.4:1). Rule kept from Phase 1: destructive text and icons sit on `background` (4.8:1 light), never on `secondary`.

Rules:

- **Variation colors follow P2 D-20 / D-17**: decrease = `--positive` + ArrowDown; increase = `foreground` (neutral) + ArrowUp; 0.0 % neutral; missing = muted text. Red is never used for an increase. Arrow, sign and `sr-only` "subió"/"bajó" always accompany color.
- **Dimmed concept rows** (D-14) use the `muted-foreground` token plus an `sr-only` label, **not** opacity (keeps the 7:1 contrast), exactly like "No suma" rows in Phase 2.
- 60/30/10: the Dashboard and both Categorías sections sit on `background`; headers, hover, expanded panels and chips on `secondary`; accent stays small.

Accent reserved for (Phase 2 list; item 6 extends to the new tab; nothing else):

1. Primary buttons: "Entrar", "Seleccionar archivos", "Agregar facturas" (still the **only** accent-filled button on any screen; "Exportar a Excel", "Agregar categoría", "Descargar ajustes", "Subir ajustes" are `outline`).
2. Dropzone drag-over state and the window drop overlay border.
3. Progress bar fill.
4. The active sort icon in any table header (including the new supplier table).
5. The 2px keyboard focus ring on all focusable elements.
6. The 2px underline of the active tab (now four tabs) and the single bar under the pointer in the monthly chart.

Destructive reserved for (Phase 1 list plus two confirms and one icon):

1. Confirm buttons of "Cerrar sesión" and "Quitar todas" (P1).
2. The login error text and the "Rechazados" value/icon (P1).
3. **New:** the "Borrar" confirm button of the delete-category dialog [D-05].
4. **New:** the "Reemplazar mis ajustes" confirm button of the replace-settings dialog [D-08].
5. **New:** the `CircleAlert` icon (not the text) of the "invalid backup file" Alert [D-08]; its message is in `foreground`, as the rejected-file rows of Phase 1.

### Primary focal point per screen

### Shell, tabs and top bar [D-01, D-19]

- Four tabs: Dashboard, Categorías, Calidad de datos, Importación **[OPEN Q2]**. `AppTab` gains `"categorias"`; `isAppTab`, `TABS` and the `Tabs` panel list in `AppShell.tsx` are extended. Same trigger styling as Phase 2 (14/600, 40px list, accent 2px underline on the active one).
- The tab list must not wrap. **Under 640px it scrolls horizontally** inside its container (`overflow-x-auto`, hidden scrollbar, `flex-none` triggers, 44px height), and the active trigger is scrolled into view when the tab changes (`scrollIntoView({ inline: "nearest" })`). Four tabs cannot fit 312px (the Phase 2 claim that three fit must also be re-checked in the verification run).

### Workbook contract (XLS-01..03, D-19..D-23)

The workbook is built by pure functions `(filteredData, mode, settings) => SheetData` (one per sheet, unit-tested, reading the **same selectors** as the Dashboard so totals match by construction) and written once with `writeExcelFile([...])` from `write-excel-file/universal`. Common rules:

- Row 1 of every sheet is the header: `fontWeight: "bold"`, `backgroundColor: "#E5E5E5"`, `wrap: true`; `stickyRowsCount: 1`. Summary sheets also have a **Total** row: bold, same fill, same formats. No formulas (static values) **[default]**, no merged cells.
- Money: real `Number` cells with format `"$#,##0.00"`; unit price `"$#,##0.00####"` (CFDI allows 6 decimals); quantity `"#,##0.######"`; exchange rate `"0.0000"`; percentages are fractions with `"0.0%"`; counts `"#,##0"`; dates are `Date` cells with `"dd/mm/yyyy"` built from the literal CFDI `Fecha` with no time-zone conversion [REGLA-05]; RFC, folio, UUID, ClaveProdServ and every code are `String` cells with `format: "@"` [XLS-03]. Amounts are rounded to 2 decimals (6 for unit price) only when the cell is written; the Total rows are the rounded exact sum, so they equal the Dashboard (a sum of the rounded rows can differ by a cent, as on screen).
- Credit notes carry negative **Monto**; the XML breakdown columns keep the XML values as they are.
- Column widths (characters): Fecha 12 · Proveedor 36 · RFC 16 · Folio 14 · UUID 38 · Tipo 16 · Estado 34 · Forma de pago 32 · Descripción 50 (wrap) · Categoría 32 · money 16 · counts 12.
- A sheet with no rows still writes its header (and Total row where applicable).
- Rows: same order as the Dashboard (Facturas: Fecha ascending then folio; Conceptos: the same, lines in XML order; summaries: net spend descending, negative nets last).
- Everything user-provided (descriptions, names) is written as text cells; a value starting with `=`, `+`, `-` or `@` must be guarded against formula injection (prefix with an apostrophe-equivalent: write as `String` with `format: "@"`, which never evaluates) **[default, security]**.

### Accessibility floor (additions to Phase 1 and 2)

- Tabs: four triggers with roving arrow keys, `aria-selected`; the scrollable tab list on phones keeps the active tab in view.
